# 016 — Follow Home Assistant's energy date picker

Status: in-review (round 1: 3 required — fixed; round 2: APPROVE)
Roadmap: stage 4 (card)
Spec sections: SPEC §4.1

## Goal
On a dashboard that has HA's own `energy-date-selection` card, the cost card uses that picker's period (same
calendar, arrows, presets as the Energy dashboard, in sync with HA's energy cards) instead of its own; elsewhere it
keeps its own picker.

## Context
- The built-in Energy panel cannot get an extra tab cleanly: it is generated by a hard-coded strategy
  (`src/panels/energy/strategies/energy-dashboard-strategy.ts`: overview / electricity / gas / water / now); only
  `hidden_cards` is configurable. A tab would need monkey-patching HA's internal strategy — rejected.
- The `energy-date-selection` card is a public Lovelace card. It stores its period in an energy collection on the
  websocket connection: `connection["_" + key]`, key = `collection_key` or `energy_<panelUrl>`
  (`src/data/energy.ts` `convertCollectionKeyToConnection`; `energy-collection-controller.ts`). Popular custom
  cards read it the same way. It is internal and changed in 2025 (per-dashboard keys), hence the fallback.

## Implementation notes
- The collection is looked up in `willUpdate` on every update until found (HA sets a new `hass` on each state
  change), so the order of the cards does not matter; the initial period comes from the collection when it is
  already there.
- Review round 1: (R1) `setConfig` detaches and re-attaches (title edit, other `collection_key`, back to `card`);
  (R2) following is opt-in, default `card`; (R3) dates are read in the zone HA used for the bounds
  (`hass.locale.time_zone` `server` → HA's zone, else the browser's) instead of "12 h inside", which failed for zones
  12 h or more apart. Suggestions applied: `hass.panelUrl` for the dashboard path; a collection whose
  `subscribe()` threw is not retried on every update; `collection_key` must start with `energy_`.
- Ported onto `master` without task 015 (tariff comparison was withdrawn in favour of tariffs configured in the
  integration): the reviewed code is unchanged apart from the comparison parts it was stacked on.
